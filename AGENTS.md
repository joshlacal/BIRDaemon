# AGENTS.md

Agent instructions for this repository (`CLAUDE.md` imports this file).

## Overview

**BIRDaemon** (`bird-daemon`) is a Bluesky DM chatbot daemon written in Rust. It logs into a Bluesky account, joins MLS-encrypted chat conversations (the `blue.catbird.chat` stack shared with Catbird iOS and catmos), decrypts incoming messages, forwards them to an LLM/agent backend, and sends the encrypted reply back into the conversation.

It is **not** a workspace — it's a single binary crate. Dependency-refresh builds pin `catbird-mls` and `catbird-atproto` by immutable Git revisions; run `scripts/check-canonical-sibling-provenance.sh` to verify the resolved core source, features, and lockfile.

## Build & Run

```bash
cd BIRDaemon
cargo build            # debug
cargo build --release  # release binary -> target/release/bird-daemon
cargo check
cargo fmt && cargo clippy --all-targets

# Run (reads config from ~/Library/Application Support/BirdDaemon/, see below)
RUST_LOG=info cargo run
```

> **Dependency refresh (2026-10-25):** use the pinned Rust 1.99.1 toolchain. Current source handles `Quarantined`, `DeviceRemoved`, and `Closed` states. See [the dependency and transport qualification notes](docs/dependency-refresh-2026-10-25.md); compilation and local fixture checks do not qualify a live bot account.

There is no README, deploy script, or systemd unit in the repo. Runtime data lives under `~/Library/Application Support/BirdDaemon/`.

## Environment Variables

The following process environment is used; other settings are in `config.json` (see below).

| Var | Where | Purpose |
|-----|-------|---------|
| `BIRD_APP_PASSWORD` | `~/Library/Application Support/BirdDaemon/.env` (loaded via `dotenvy`) | Bluesky **app password**. Required for the credential session; also the migration fallback for an existing MLS database with no separate key file. |
| `BIRD_NEST_BASE_URL` | process env | Required for the clean-chat authority flow; without it the chat loop stays disabled. |
| `RUST_LOG` | process env | `tracing` `EnvFilter`; defaults to `info` if unset. |

There is no `.env.example`. The `.env` file must contain `BIRD_APP_PASSWORD=...`.

## Configuration (`config.json`)

Loaded from `~/Library/Application Support/BirdDaemon/config.json` (`src/config.rs`, `BirdConfig`). **All fields are required** — they are non-`Option` with no `#[serde(default)]`, so a missing key makes `load_config()` fail at startup. Keys are camelCase:

```json
{
  "handle": "bot.bsky.social",
  "llmBackend": "...",
  "llmBaseURL": "https://...",
  "llmApiKey": "...",
  "llmModel": "...",
  "systemPrompt": "...",
  "acceptChatRequests": true,
  "replyToAllMessages": true,
  "maxReplyCharacters": 1000
}
```

Note: `llmBaseURL` / `llmApiKey` / `llmModel` are still required in the JSON, but the **active reply path ignores them** (see Data Flow). They feed the dormant `LlmClient` in `src/llm.rs`, not the wired-up `BridgeClient`.

Runtime files created alongside `config.json`: `keychain.json`, `credentials.json`, `bird.db` (app storage), and `mls-state/<sanitized-did>.db` (encrypted MLS/OpenMLS state).

## Architecture / Data Flow

Entry point: `src/main.rs`.

1. **Auth** — Authenticates to Bluesky via `jacquard` `MemoryCredentialSession` using the **legacy app password** (not OAuth). Resolves DID + PDS endpoint.
2. **API client** (`src/xrpc_client.rs`, `BirdApiClient`) — Implements `catbird_mls::orchestrator::MLSAPIClient`. Prepared canonical chat requests use an admitted opaque Nest session and actor-device binding. PDS repository helpers retain the Jacquard bearer session and token refresh; it is not substituted for chat authority.
3. **MLS context + orchestrator** — `MLSContext::new(...)` opens the per-DID SQLCipher DB with its retained key. `MLSOrchestrator` uses `SqliteStorage`, `FileCredentialStore`, and `FileKeychain`, including per-DID epoch-secret ownership. After initialization, startup restores or establishes Nest authority and reconciles signed device enrollment before entering the chat loop.
4. **Event loop** (`src/bot.rs`, `BirdBot::run`) — The WebSocket adapter decodes generated canonical DAG-CBOR envelopes and delegates fresh inventory/ticket preparation, durable cursor fencing, and entry processing to the shared orchestrator. Returned live messages enter the existing bridge reply handler. Legacy `Message`/`GroupReset` decoding remains; reset handling is persist-only. A 30s timer drives sync and deferred recovery. Reconnect catch-up does not add an offline LLM reply queue.
5. **LLM reply** — The **live** path is the **bridge** (`src/bridge_client.rs`, `BridgeClient`): `main.rs` constructs `BridgeClient::new("http://127.0.0.1:8789")`. Decrypted plaintext is POSTed to the `mls-chat-channel` bridge (`/message`), then it polls `/reply/:conversation_id` for the response generated by Claude Code. The reply is sent back via `orchestrator.send_message`.
   - `src/llm.rs` (`LlmClient`, an OpenClaw / OpenAI-compatible chat-completions gateway using `llmBaseURL`/`llmApiKey`/`llmModel`) is the **alternate, currently-unwired** LLM backend. It is not constructed in `main.rs`. Don't describe it as the active path.

## Key Dependencies

- **`catbird_mls` (immutable Git dependency)** — MLS protocol + orchestrator (OpenMLS, recovery policy, sync). BIRDaemon implements the orchestrator's `MLSAPIClient` / `MLSStorageBackend` / `CredentialStore` / `KeychainAccess` traits and consumes its types (`ConversationState`, `IncomingEnvelope`, etc.) **directly**. Built with `default-features = false`.
- **`catbird-atproto` (immutable Git dependency)** — Generated AT Protocol types with correct `$bytes` serialization.
- **`jacquard` 0.13** (+ `jacquard-common`, `jacquard-identity`, at the coordinated immutable revision) — ATProto client: auth, identity resolution, session/token lifecycle.
- Shared OpenMLS provider/traits/credential crates use one coordinated immutable fork revision; do not mix registry and path/Git identities.
- `rusqlite` with `bundled-sqlcipher`, `tokio-tungstenite` (WebSocket), `ciborium` (DAG-CBOR frames), `reqwest` (rustls).

## Gotchas

- **Build breaks on `catbird-mls` evolution.** Because BIRDaemon matches on / constructs upstream orchestrator types directly, adding an enum variant or struct field in `catbird-mls` breaks compilation here (the workspace "Jacquard struct-evolution breaks consumers" pattern). Keep terminal states and integer range validation intact when reconciling those changes.
- **CMake 4.x / `audiopus_sys` (workspace backlog N2):** `catbird-mls` transitively pulls in `audiopus_sys`, which fails under CMake 4.x. **This crate already handles it** — `.cargo/config.toml` sets `CMAKE_POLICY_VERSION_MINIMUM = "3.5"`, so no manual export is needed when building from this directory. (Unlike sibling crates, where you must export it yourself.)
- **The bridge must be running.** The live reply path requires the `mls-chat-channel` bridge listening on `http://127.0.0.1:8789`. If it's down, replies fail (the daemon logs the error but sends nothing).
- **Preserve per-DID key custody.** New MLS databases use an independent random key retained in `mls-state/<sanitized-did>.key`. Existing databases without a separate key retain the historical app-password fallback. Never replace either database/key material during dependency validation.
- **Never inline External Commits.** The bot intentionally avoids proactive/inline rejoins — it flags `NEEDS_REJOIN` and lets the 30s sync loop drive recovery. This is deliberate epoch-inflation discipline; preserve it (`record_group_reset` is persist-only, recovery is deferred/reactive).
- **Authority admission is explicit.** The chat loop starts only after the Nest session, actor device, auth generation, signer and verified DPoP thumbprint agree. Dependency validation must not use a real account or revoke existing devices.
- **Messages beyond the epoch retention window are dropped.** `MAX_PAST_EPOCHS = 5`; messages from epochs older than `local_epoch - 5` are discarded rather than recovered.
- **Pending Welcome join is fail-closed until shared core exposes a post-join acknowledgement hook.** BIRDaemon fetches device-addressed Welcomes only from the retained `getConversations` inventory session and can construct the canonical `acknowledgeWelcome` mutation, but it must acknowledge only after `process_welcome` and durable local join succeed. The current `MLSAPIClient::get_welcome` contract has no such success callback, so BIRDaemon caches the exact Welcome and returns an explicit unsupported error instead of acknowledging early or pretending the join is complete.
- **Raw key-package lookup and hash reconciliation are intentionally unsupported.** The clean-chat protocol exposes `getDevices` addressability/counts and signed `replenishKeyPackages`, but no endpoint that exports reserved KeyPackage bytes or implements the old `syncKeyPackages` mutation. BIRDaemon returns explicit errors for those legacy trait methods; it never falls back to nonexistent `blue.catbird.chat.getKeyPackages` or reports a fabricated zero-change sync.
